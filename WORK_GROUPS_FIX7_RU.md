# FIX7 — рабочие группы и назначение задач

## Что изменено

- В левом меню после **«Команды»** добавлено **«Управление командой»** (только для системного администратора), затем **«Группы»**. «Управление командой» убрано из списка пользовательских настроек, чтобы не дублироваться; старый URL оставлен для совместимости.
- Старые группы, которые отвечают за глобальные права, в интерфейсе переименованы в **«Роли доступа»**. Их backend-таблицы не переименовывались, поэтому существующие права и данные сохраняются.
- Добавлены отдельные **рабочие группы**. Они используются только для организации сотрудников и назначения задач и **никогда не дают прав доступа**.
- У рабочей группы есть название, описание, участники и один глава. Пользователь может состоять в нескольких рабочих группах независимо от своей роли доступа.
- В карточке задачи теперь можно назначать:
  - отдельных пользователей;
  - одну или несколько рабочих групп;
  - одновременно пользователей и группы.
- При назначении рабочей группы её участники материализуются как обычные assignee Vikunja. Поэтому продолжают работать аватары, фильтры, уведомления и Kanban.
- На Kanban-карточке показываются названия назначенных рабочих групп.

## Важная логика прав

Рабочая группа не открывает проект. Если участник группы не имеет доступа к проекту, он остаётся участником группы, но не назначается исполнителем задачи этого проекта. UI показывает количество пропущенных участников.

Глава рабочей группы — только организационная роль внутри группы. Само назначение главой не выдаёт никаких системных или проектных прав.

## Сохранение источника назначения

В БД хранится источник назначения исполнителя:

- `direct` — пользователь назначен лично;
- `work_group` — пользователь назначен через рабочую группу.

Благодаря этому:

- снятие группы не удаляет личное назначение того же пользователя;
- если пользователь входит в две назначенные группы, снятие одной группы не удаляет его, пока остаётся вторая;
- изменение состава группы синхронизирует уже назначенные этой группе задачи;
- удаление группы снимает только назначения, пришедшие через неё.

## Новые таблицы

Миграция `20260819150000` создаёт:

- `work_groups`
- `work_group_members`
- `task_work_group_assignees`
- `task_assignee_sources`

Существующие строки `task_assignees` автоматически помечаются как личные (`direct`), чтобы обновление не изменило старые назначения.

## Установка поверх FIX6

Распакуйте `Vikunja_Work_Groups_Task_Assignment_FIX7.zip` в корень текущего исходника Vikunja с заменой файлов.

Затем:

```powershell
.\BUILD-WINDOWS-FIXED-v2.ps1
```

Запустите новый:

```powershell
.\release\vikunja.exe
```

При первом запуске миграция выполнится автоматически. Существующую SQLite-базу удалять не нужно. Настройки и токен Wialon сохраняются.
