# FIX13 — Custom Client Fields

База: **Vikunja Custom GreenTech CRM History v2.5.0 SOURCE FIX12**.

## Что добавлено

В самом низу вкладки **«Клиент»** появился блок **«Пользовательские поля»**.

Каждая строка содержит:

- название поля;
- значение поля;
- отдельную кнопку сохранения;
- удаление.

Количество пользовательских полей у клиента не ограничено приложением.

Примеры:

- `Мощность СЭС` → `150 кВт`
- `Номер договора` → `GE-2026-0142`
- `Старый CRM ID` → `88341`
- `Особые условия` → `Оплата 50/50`

FIX13 намеренно реализует только универсальную пару **«название → значение»**. Типизированные поля Date / Number / Checkbox / Dropdown можно добавить позднее отдельным расширением без изменения текущего интерфейса.

## История клиента

Изменения пользовательских полей автоматически попадают во вкладку **«История»**:

- `custom_field_created` — поле добавлено;
- `custom_field_updated` — изменено название и/или значение;
- `custom_field_deleted` — поле удалено.

Для изменения значения история хранит старое и новое значения. При переименовании отдельно фиксируются старое и новое названия.

События являются системными и не удаляются через интерфейс ручных активностей.

## База данных

Новая миграция:

`20260820140000`

Создаётся таблица:

`client_custom_fields`

Поля таблицы:

- `id`
- `project_id`
- `name`
- `value`
- `position`
- `created`
- `updated`

Существующую SQLite-базу удалять **не нужно**.

## API v2

Добавлены endpoints:

- `GET /api/v2/projects/{project}/client/custom-fields`
- `POST /api/v2/projects/{project}/client/custom-fields`
- `PUT /api/v2/projects/{project}/client/custom-fields/{field}`
- `DELETE /api/v2/projects/{project}/client/custom-fields/{field}`

## Права

- просмотр наследуется от права чтения проекта;
- создание, изменение и удаление требуют права изменения проекта;
- публичные link-share CRM-поля не получают.

## Удаление клиента

При удалении проекта/клиента связанные строки `client_custom_fields` удаляются вместе с остальными CRM-данными.

## Установка патча

1. Использовать исходники с установленным FIX12.
2. Остановить Vikunja.
3. Распаковать `Vikunja_CRM_Custom_Client_Fields_FIX13.zip` в корень исходников с заменой файлов.
4. Выполнить:

```powershell
.\BUILD-WINDOWS-FIXED-v2.ps1
```

5. Запустить новый `release\vikunja.exe`.
6. Обновить браузер через `Ctrl+F5`.

Миграция выполнится автоматически при первом запуске нового backend.

## Проверки при подготовке

- Go-файлы отформатированы `gofmt`;
- синтаксис изменённых Go-файлов проверен парсером Go;
- frontend прошёл полный `vue-tsc --noEmit` без ошибок;
- JSON локализаций проверен;
- добавлен web-тест `huma_client_custom_fields_test.go` для CRUD, истории и приватности.

Полный backend test/build в контейнере не выполняется из-за отсутствия требуемого Go 1.26.4 и недоступности загрузки Go-модулей. Финальная production-сборка выполняется штатным Windows-скриптом проекта.
